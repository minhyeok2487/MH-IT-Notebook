OSPF는 LSDB(Link State Database)를 구성하고 라우터 간에 라우팅 정보를 교환하기 위해 **11가지 LSA(Link State Advertisement) 타입**을 사용합니다. 각 LSA 타입은 고유한 목적과 **플러딩 범위(Flooding Scope)** — 즉 영역 내부에서만 도는지, 여러 영역으로 넘어가는지, OSPF 도메인 전체로 퍼지는지 — 를 가집니다.

이 문서는 OSPFv2 기준으로, **토폴로지 하나를 처음부터 끝까지 그대로 재사용**하면서 11가지 타입을 전부 훑습니다. Type 1·2·3·4·5·7은 실제 `show ip ospf database` 출력 형식의 예시로, 나머지(6·8·9·10·11)는 개념 위주로 설명합니다.

## 1. LSA란 무엇인가

LSA(Link-State Advertisement)는 프로토콜도 알고리즘도 아니고, **라우터가 뿌리는 자기소개 쪽지 한 장**입니다. "나는 R1이고, 내 인터페이스는 이렇게 생겼고, 이웃은 이렇다" — 딱 이 정보만 담은 작은 데이터 조각입니다.

- 라우터가 자기 링크 정보를 LSA라는 쪽지에 적어서 → 이웃에게 뿌리고(플러딩) → 이웃도 그대로 복사해서 또 뿌립니다.
- 영역 안 모든 라우터가 이 쪽지들을 다 모아 보관하는 서랍이 **LSDB**입니다.
- LSDB에 쌓인 쪽지를 전부 조합하면 네트워크 전체 지도가 완성되고, 그 지도로 SPF를 계산해 최단 경로를 뽑습니다.

타입이 11개나 되는 이유는 쪽지 양식이 상황마다 다르기 때문입니다 — 내용물은 다 "여기 뭐가 있다"는 사실 보고서이고, **누가 쓰는지 · 어디까지 퍼지는지**만 다릅니다.

## 2. 핵심 요약

- OSPF의 LSA는 총 **11종류(Type 1~11)** 이며, 각각 **누가 생성하는지** 와 **어디까지 퍼지는지** 가 다릅니다.
- **Type 1(Router LSA)** 과 **Type 2(Network LSA)** 는 영역 내부(intra-area)에만 머무릅니다 — 라우팅 테이블의 **O** 표시가 여기서 나옵니다.
- **Type 3(Summary LSA)** 은 ABR이 다른 영역으로 넘겨주는 LSA로, 라우팅 테이블의 **O IA** 표시가 여기서 나옵니다.
- **Type 4(Summary ASBR LSA)** 는 다른 영역의 라우터들이 ASBR의 위치를 찾을 수 있도록 ABR이 생성합니다.
- **Type 5(External LSA)** 는 ASBR이 재분배(redistribution)한 외부 경로를 OSPF 도메인 전체에 퍼뜨리며, 라우팅 테이블의 **O E1 / O E2**로 나타납니다.
- **Type 6(Multicast LSA)** 과 **Type 8(External Attribute LSA)** 은 사실상 미사용/미구현 타입입니다.
- **Type 7(NSSA External LSA)** 은 NSSA 영역에서 Type 5 대신 쓰이며, 라우팅 테이블의 **N1 / N2**로 나타납니다.
- **Type 9/10/11**은 모두 **Opaque LSA**로, OSPF 자체는 내용을 해석하지 않고 다른 기능(Graceful Restart, MPLS TE, Segment Routing 등)을 위한 컨테이너 역할만 합니다. 이 셋의 차이는 오직 **플러딩 범위**(link-local / area-local / AS-wide)입니다.

## 3. 이 문서에서 쓰는 토폴로지

앞선 [OSPF Multi-Area Configuration](/posts/05-ospf-multi-area/)의 그 토폴로지를 처음부터 끝까지 그대로 씁니다.

![R1·R2가 Area 0의 ABR, R3는 Area 1, R4는 Area 2에 있는 토폴로지](/images/ospf-lsa-types/topology.png)

- **R1**(router-id 1.1.1.1)과 **R2**(router-id 2.2.2.2)는 **ABR**입니다. 둘은 Gi0/1로 직접 연결되어 **Area 0**(192.168.12.0/24)를 이룹니다. 이 링크는 기본 이더넷(broadcast)이라 **R1·R2만 있어도 DR/BDR이 선출**됩니다 — Router ID가 더 높은 **R2가 DR**, **R1이 BDR**입니다.
- **R3**(router-id는 자동으로 루프백 IP인 3.3.3.3)는 R1의 Gi0/2와 연결되어 **Area 1**(192.168.13.0/24) 안에만 있고, 루프백 `3.3.3.3/32`를 갖습니다.
- **R4**(router-id 4.4.4.4)는 R2의 Gi0/2와 연결되어 **Area 2**(192.168.24.0/24) 안에만 있고, 루프백 `4.4.4.4/32`를 갖습니다.
- 모든 링크는 **GigabitEthernet**이라 [OSPF 기본 설정](/posts/04-ospf-basic-config/)에서 다룬 참조 대역폭 기본값(100Mbit) 기준으로 **Cost가 전부 1**입니다. 루프백도 IOS 기본값으로 Cost 1입니다.

뒤에서 R3는 RIP도 겸해서 돌리다가 **ASBR**이 되고, Area 1은 나중에 **NSSA**로도 바뀝니다 — 전부 같은 4대(R1~R4)로 진행됩니다.

## 4. LSA 타입 전체 개요

| LSA Type | 이름 | 생성 주체 (Generated By) | 플러딩 범위 (Flooding Scope) |
| --- | --- | --- | --- |
| 1 | Router LSA | 모든 라우터 | 영역 내부 |
| 2 | Network LSA | DR | 영역 내부 |
| 3 | Summary LSA | ABR | 다른 영역으로 |
| 4 | Summary ASBR LSA | ABR | 다른 영역으로 |
| 5 | External LSA | ASBR | OSPF 도메인 전체 |
| 6 | Multicast LSA | N/A | N/A (미사용) |
| 7 | NSSA External LSA | ASBR (NSSA 내) | NSSA 영역 내부만 |
| 8 | External Attribute LSA | N/A | N/A (미사용) |
| 9 | Opaque LSA (link-local) | 라우터 | 링크-로컬 범위 |
| 10 | Opaque LSA (area-local) | 라우터 | 영역 내부 |
| 11 | Opaque LSA (AS-wide) | 라우터 | OSPF 도메인 전체 |

## 5. LSA Type 1 — Router LSA

영역 내 **모든 라우터**가 Type 1 Router LSA를 생성해 **영역 내부에만** 플러딩합니다. R1이 "나는 이런 인터페이스들을 갖고 있다"는 자기소개 쪽지를 써서 같은 영역 라우터들에게 돌리는 것입니다.

R1은 인터페이스 두 개(Gi0/1→R2, Gi0/2→R3)를 갖고 있습니다. 이 둘을 그냥 "인터페이스가 있다"고만 적으면 정보가 부족합니다 — 옆에 라우터가 몇 대나 붙어 있는지, 어떻게 도달하는지가 링크마다 다르기 때문입니다. 그래서 R1은 링크를 한 줄씩 적을 때마다 **"이 링크가 어떤 성격이냐"는 태그**를 함께 붙이는데, 이게 **Link Type**입니다.

| Link Type | 설명 | Link ID |
| --- | --- | --- |
| 1 | Point-to-point (다른 라우터와 1:1 연결) | 이웃 라우터의 Router ID |
| 2 | Transit network (DR이 있는 다중 접속망) | DR의 인터페이스 IP |
| 3 | Stub network (이웃 없는 네트워크, 루프백 포함) | 네트워크 주소 |
| 4 | Virtual link | 이웃 라우터의 Router ID |

- **R1의 Gi0/1(→R2)**: 이더넷 기본값(broadcast)이라 DR/BDR이 있는 **transit network(Link Type 2)** 로 태그가 붙고, Link ID는 DR인 R2의 인터페이스 IP(192.168.12.2)입니다.
- **R1의 Gi0/2(→R3)**: 역시 이더넷이라 기본은 transit이지만, 상대가 R3 하나뿐이라 [OSPF 기본 설정](/posts/04-ospf-basic-config/)에서 다룬 `ip ospf network point-to-point`를 걸면 **point-to-point(Link Type 1)** 로 바뀝니다. 이 경우 Link ID는 R3의 Router ID(3.3.3.3)입니다.
- **R3의 Lo0(3.3.3.3/32)**: 이웃이 없는 링크라 **stub network(Link Type 3)** 로 태그가 붙고, Link ID는 네트워크 주소(3.3.3.3) 그 자체입니다.
- **virtual link(Link Type 4)**: 어떤 영역이 Area 0에 직접 붙어 있지 못할 때, 다른 영역을 거쳐 논리적으로 이어주는 가상 링크에만 붙는 태그입니다. 우리 토폴로지에서는 모든 영역이 Area 0에 직접 붙어 있어 등장하지 않습니다.

R1이 Gi0/2를 point-to-point로 바꿨다고 가정하고, R1의 Router LSA를 확인하면 다음과 같은 형태가 됩니다.

```
R1#show ip ospf database router self-originate

            OSPF Router with ID (1.1.1.1) (Process ID 1)

                Router Link States (Area 0)

  LS age: 120
  Options: (No TOS-capability, DC)
  LS Type: Router Links
  Link State ID: 1.1.1.1
  Advertising Router: 1.1.1.1
  LS Seq Number: 80000003
  Checksum: 0x4A21
  Length: 36
  Number of Links: 1

    Link connected to: a Transit Network
     (Link ID) Designated Router address: 192.168.12.2
     (Link Data) Router Interface address: 192.168.12.1
      TOS 0 Metrics: 1
```

> R1의 Area 0(Gi0/1) LSA만 골라 봤습니다. R1은 Area 1(Gi0/2)에도 별도의 Router LSA를 하나 더 발행합니다 — **Router LSA는 라우터가 속한 영역마다 따로** 만들어지기 때문입니다.

필드 하나씩 보면: **Link State ID/Advertising Router**는 항상 이 LSA를 만든 라우터 자신(1.1.1.1)이고, **Link ID(192.168.12.2)** 는 DR인 R2의 인터페이스 주소, **Link Data(192.168.12.1)** 는 R1 자신의 인터페이스 주소입니다. **TOS 0 Metrics**가 Cost이며, Gigabit이라 1입니다.

Router LSA는 **항상 영역 내부에만 머뭅니다.** 라우팅 테이블에서 같은 영역 안의 경로가 **O**(intra-area)로 표시되는 것이 바로 이 Type 1 LSA에서 비롯됩니다.

## 6. LSA Type 2 — Network LSA

앞서 R1의 Gi0/1 — R2와 함께 물려 있는 그 Area 0 구간을 다시 떠올려 보겠습니다. R1은 자기 Router LSA에 이 링크를 "transit network"라고 태그만 달아뒀을 뿐, 그 세그먼트에 정확히 누가누가 있는지는 적지 않았습니다. R2도 자기 쪽지에 똑같이 "나도 이 세그먼트에 있다"고만 적을 뿐입니다. 그러면 "이 세그먼트에 정확히 몇 대가, 누가 붙어 있는가"라는 정보는 누구도 완전하게 갖고 있지 않게 됩니다.

이 빈틈을 메우는 게 **Type 2 Network LSA**입니다. 이 세그먼트에서 DR로 뽑힌 라우터(**R2**, Router ID가 더 높아서 DR이 됐습니다)가 딱 하나의 쪽지를 더 작성합니다. 이번엔 "나는 이런 링크를 가졌다"가 아니라, **"이 192.168.12.0/24 세그먼트에는 R1, R2(자기 자신)가 붙어 있고, 서브넷 마스크는 이렇다"** 는 명단입니다.

```
R2#show ip ospf database network self-originate

            OSPF Router with ID (2.2.2.2) (Process ID 1)

                Net Link States (Area 0)

  LS age: 118
  Options: (No TOS-capability, DC)
  LS Type: Network Links
  Link State ID: 192.168.12.2 (address of Designated Router)
  Advertising Router: 2.2.2.2
  LS Seq Number: 80000001
  Checksum: 0x9F3C
  Length: 32
  Network Mask: /24
        Attached Router: 2.2.2.2
        Attached Router: 1.1.1.1
```

Router LSA가 라우터 한 대가 자기 자신을 소개하는 쪽지라면, Network LSA는 **DR이 그 세그먼트 전체를 대표해서 작성하는 출석부**인 셈입니다. **Link State ID는 Router ID가 아니라 DR의 인터페이스 IP**라는 점이 Type 1과 가장 다른 부분입니다.

그래서 Network LSA는 **DR/BDR 선출이 필요한 broadcast·non-broadcast 네트워크 타입에서만** 생성됩니다. Point-to-point나 point-to-multipoint(non-broadcast)처럼 애초에 DR이 없는 타입에서는 이 LSA 자체가 만들어지지 않습니다 — 앞서 R1-R3처럼 point-to-point로 바꾼 링크에는 Network LSA가 없습니다. DR이 없으면 출석부를 쓸 사람이 없기 때문입니다.

## 7. LSA Type 3 — Summary LSA

R3은 Area 1에만 있고, 자기 루프백 3.3.3.3/32를 Router LSA에 적어 **Area 1 안에서만** 플러딩합니다. 앞서 봤듯 Router LSA는 자기 영역 밖으로 절대 못 나가는 쪽지라서, 이 쪽지는 Area 1 서랍(LSDB)에만 쌓입니다. 문제는 Area 0에 있는 R2나 Area 2에 있는 R4도 결국 3.3.3.3에 도달할 방법을 알아야 한다는 것입니다. 이들은 Area 1 서랍을 아예 볼 수가 없는데, 어떻게 그 안의 정보를 알까요?

여기서 **ABR인 R1**이 등장합니다. R1은 Area 1과 Area 0 양쪽에 발을 걸치고 있으므로, Area 1 서랍에서 3.3.3.3/32라는 프리픽스를 보고 그 내용을 **새 쪽지에 옮겨 적어** Area 0으로 넘깁니다. 이 새 쪽지가 바로 **Type 3 Summary LSA**입니다 — R3가 원래 쓴 Router LSA를 그대로 복사해서 넘기는 게 아니라, R1이 "Area 1에 이런 프리픽스가 있다더라"는 **완전히 다른 형식의 쪽지를 새로 씁니다.**

```
R1#show ip ospf database summary self-originate

            OSPF Router with ID (1.1.1.1) (Process ID 1)

                Summary Net Link States (Area 0)

  LS age: 30
  Options: (No TOS-capability, DC)
  LS Type: Summary Links(Network)
  Link State ID: 3.3.3.3 (summary Network Number)
  Advertising Router: 1.1.1.1
  LS Seq Number: 80000001
  Checksum: 0x2C11
  Length: 28
  Network Mask: /32
        TOS: 0  Metric: 2
```

Metric이 **2**인 이유: R1 자신의 Gi0/2 링크 Cost 1 + R3 루프백 자체 Cost 1 = 2. R1은 "내가 여기서부터 3.3.3.3까지 가는 데 드는 비용은 2"라고 Area 0에 광고하는 것입니다.

이 쪽지가 Area 0에 들어오면, 이번엔 Area 0/Area 2에 발을 걸친 ABR인 R2가 똑같은 일을 한 번 더 합니다. R2도 R1이 쓴 쪽지를 그대로 옆으로 넘기는 게 아니라, 그 내용을 보고 **자기 이름으로 또 새 쪽지를 써서** Area 2로 넘깁니다.

```
R2#show ip ospf database summary self-originate

            OSPF Router with ID (2.2.2.2) (Process ID 1)

                Summary Net Link States (Area 2)

  LS age: 12
  Options: (No TOS-capability, DC)
  LS Type: Summary Links(Network)
  Link State ID: 3.3.3.3 (summary Network Number)
  Advertising Router: 2.2.2.2
  LS Seq Number: 80000001
  Checksum: 0x18F0
  Length: 28
  Network Mask: /32
        TOS: 0  Metric: 3
```

> Advertising Router가 R1(1.1.1.1)에서 **R2(2.2.2.2)로 바뀐 것**을 주목하세요. R2가 원본을 그대로 넘긴 게 아니라 처음부터 새로 만든 증거입니다. Metric도 R1이 광고한 2에 R2 자신의 R1행 링크 Cost 1을 더해 **3**이 됐습니다. 그래서 "R2가 만든 Type 3 LSA를 R3가 그대로 넘긴다"가 아니라, **영역을 하나 건널 때마다 그 경계의 ABR이 매번 새로 씁니다.** 이걸 **재생성(regenerate)** 이라고 부릅니다.

R4는 이 쪽지를 받고 자기 링크 Cost 1을 더해 최종적으로 **4**를 계산합니다.

```
R4#show ip route ospf
      3.0.0.0/32 is subnetted, 1 subnets
O IA     3.3.3.3 [110/4] via 192.168.24.2, 00:05:12, GigabitEthernet0/1
```

R3의 루프백 Cost 1이 ABR을 두 번 거치며 **1 → 2 → 3 → 4**로 누적되는 과정 전체가 이렇게 추적됩니다. 라우팅 테이블에서 **O IA** 항목을 본다면 바로 이 Type 3 Summary LSA를 보고 있는 것입니다.

한 가지 오해하기 쉬운 부분: 이름이 "Summary(요약)"라고 해서 여러 프리픽스를 하나로 축약해준다는 뜻이 아닙니다. R3의 3.3.3.3/32는 R1을 거치면서도 3.3.3.3/32 그대로 넘어갑니다. OSPF는 기본적으로 아무것도 요약하지 않고, `area range` 같은 명령으로 사람이 직접 축약을 지시해야만 요약이 일어납니다.

## 8. LSA Type 4 — Summary ASBR LSA

R3가 이번엔 회사 다른 부서에서 쓰는 RIP 라우터와도 연결돼서 거기서 배운 경로를 OSPF로 재분배(redistribute)하기 시작했다고 해봅시다. 이 순간 R3는 **ASBR(Autonomous System Border Router)** — OSPF 바깥 세상과 연결된 관문 라우터 — 가 됩니다.

R3는 자기 Router LSA에 "나는 ASBR이다"라는 표시(비트) 하나를 켜서 Area 1에 플러딩합니다. 문제는 이 Router LSA도 Type 1이라 **Area 1을 못 벗어난다**는 것입니다. Area 0의 R2나 Area 2의 R4는 "R3가 외부로 나가는 문이다"라는 사실 자체를 알 방법이 없습니다.

그래서 ABR인 R1이 R3의 ASBR 비트를 보고, **Type 4 Summary ASBR LSA**라는 새 쪽지를 씁니다.

```
R1#show ip ospf database asbr-summary self-originate

            OSPF Router with ID (1.1.1.1) (Process ID 1)

                Summary ASB Link States (Area 0)

  LS age: 30
  Options: (No TOS-capability, DC)
  LS Type: Summary Links(AS Boundary Router)
  Link State ID: 3.3.3.3 (AS Boundary Router address)
  Advertising Router: 1.1.1.1
  LS Seq Number: 80000001
  Checksum: 0x3B0A
  Length: 28
  Network Mask: 0.0.0.0
        TOS: 0  Metric: 2
```

내용은 딱 하나 — "R3라는 라우터가 ASBR이고, 거기까지 가려면 이쪽으로 오면 된다"는 **위치 안내**뿐입니다. Type 3와 형식은 거의 같지만 Network Mask가 `0.0.0.0`인 점이 다릅니다 — 특정 네트워크가 아니라 **라우터 하나(ASBR)의 위치**를 가리키기 때문입니다. 이 쪽지는 앞서 Type 3가 그랬듯 Area 0으로 넘어가고, R2가 다시 재생성해서 Area 2의 R4까지 전달됩니다.

> Type 4는 ASBR과 **다른 영역**에 있는 라우터에게만 필요합니다. R3와 같은 Area 1 안에 있는 라우터는 R3의 Type 1 LSA만 봐도 ASBR 비트를 바로 확인할 수 있어서 Type 4가 필요 없습니다. 또 Stub 영역은 애초에 외부 경로(Type 5)를 받지 않기로 약속된 영역이라, 그 위치 안내인 Type 4도 함께 차단됩니다.

## 9. LSA Type 5 — External LSA

RIP 라우터에 있던 프리픽스 5.5.5.0/24가 R3를 통해 OSPF로 재분배됐다고 해봅시다. R3는 "여기 5.5.5.0/24라는 외부 네트워크가 있고, 거기까지 가는 외부 코스트는 20이다"라는 내용의 **Type 5 External LSA**를 새로 씁니다. Type 4가 "R3라는 문지기가 어디 있다"는 위치 안내였다면, Type 5는 **그 문 너머에 실제로 뭐가 있는지**를 적은 쪽지입니다 — 그래서 Type 5만 있고 Type 4가 없으면 무용지물입니다. R3까지 어떻게 가는지를 모르니까요.

```
R3#show ip ospf database external self-originate

            OSPF Router with ID (3.3.3.3) (Process ID 1)

                Type-5 AS External Link States

  LS age: 15
  Options: (No TOS-capability, DC)
  LS Type: AS External Link
  Link State ID: 5.5.5.0 (External Network Number)
  Advertising Router: 3.3.3.3
  LS Seq Number: 80000001
  Checksum: 0x77A2
  Length: 36
  Network Mask: /24
        Metric Type: 2 (Larger than any link state path)
        TOS: 0
        Metric: 20
        Forward Address: 0.0.0.0
```

재분배된 경로를 라우팅 테이블에서 보면 **O E1** 또는 **O E2**로 나타나는데, 둘의 차이는 "R3가 매긴 외부 코스트 20을 그대로 믿을 것이냐, R3까지 가는 내 몫의 코스트도 얹을 것이냐"입니다. 기본값인 **E2**는 R3가 적어준 외부 코스트 20만 그대로 씁니다 — R4든 R2든 상관없이 전부 **20**으로 동일하게 보입니다(위 출력의 `Metric Type: 2`가 이것입니다).

```
R4#show ip route ospf | include 5.5.5.0
O E2  5.5.5.0/24 [110/20] via 192.168.24.2, 00:01:40, GigabitEthernet0/1
```

반면 **E1**은 거기에 "나부터 R3까지 가는 내부 OSPF 코스트"를 더합니다. R4에서 R3까지 가는 내부 코스트는 앞서 Type 3에서 계산한 것과 같은 경로로 **3**(R4→R2 1, R2→R1 1, R1→R3 1)이므로, E1로 재분배했다면 R4는 **20 + 3 = 23**으로 봤을 것입니다. 즉 E2는 "ASBR 말만 믿는다", E1은 "내가 거기까지 가는 수고도 계산에 넣는다"는 차이입니다.

## 10. LSA Type 6 — Multicast LSA (사실상 미사용)

Type 6은 **한 번도 제대로 쓰인 적 없는 쪽지 양식**이라고 생각하면 됩니다. 예전에 누군가 "OSPF로 멀티캐스트 수신자 위치도 알려주면 어떨까?"라는 아이디어(MOSPF, RFC 1584)를 냈고, 그걸 위해 만든 게 Type 6 Multicast LSA입니다. 호스트가 멀티캐스트 그룹에 들어오면 라우터가 이 쪽지를 써서 "여기 수신자가 있다"고 알리는 구상이었습니다.

문제는 멀티캐스트 그룹이 하나 생기고 없어질 때마다 전체 라우터가 상태를 관리하고 SPF를 다시 돌려야 해서 **감당이 안 됐다**는 것입니다. 그래서 실제로 채택되지 않았고, 지금은 멀티캐스트에 **PIM**이라는 완전히 다른 프로토콜을 씁니다. Type 6은 그냥 "이런 타입 번호가 예약돼 있다"는 정도로만 기억해도 충분합니다.

## 11. LSA Type 7 — NSSA External LSA

이번엔 R3가 있는 Area 1이 알고 보니 **NSSA(Not-So-Stubby Area)**로 설정돼 있었다고 해봅시다. NSSA는 "외부에서 굴러들어온 Type 5 External LSA는 절대 안으로 들이지 않는다"는 규칙을 가진 특수한 영역입니다. 그런데 R3는 여전히 RIP을 재분배하는 ASBR입니다. Type 5를 쓰면 Area 1 안에서부터 거부당하니, R3는 **Type 7 NSSA External LSA**라는, 내용은 Type 5와 완전히 똑같지만 이름만 다른 쪽지를 씁니다. NSSA 규칙은 "Type 5라는 이름"만 걸러내기 때문에, Type 7은 검문을 통과해서 Area 1 안에서 플러딩됩니다.

```
R3#show ip ospf database nssa-external self-originate

            OSPF Router with ID (3.3.3.3) (Process ID 1)

                Type-7 AS External Link States (Area 1)

  LS age: 8
  Options: (No TOS-capability, N, DC)
  LS Type: NSSA External Link
  Link State ID: 5.5.5.0 (External Network Number)
  Advertising Router: 3.3.3.3
  LS Seq Number: 80000001
  Checksum: 0x6591
  Length: 36
  Network Mask: /24
        Metric Type: 2 (Larger than any link state path)
        TOS: 0
        Metric: 20
        Forward Address: 0.0.0.0
```

이 쪽지가 ABR인 R1에게 도착하면, R1은 Area 0으로 넘기기 전에 **Type 7을 Type 5로 다시 써서(번역·translate)** 내보냅니다. Area 0부터는 NSSA가 아니니 정상적인 Type 5로 돌아다녀도 문제가 없기 때문입니다. 그래서 라우팅 테이블에서 NSSA 안에 있는 라우터는 이 경로를 **N1 / N2**로 보고, NSSA 밖의 라우터는 번역을 거친 뒤라 **E1 / E2**로 봅니다 — N1은 E1로, N2는 E2로 그대로 대응됩니다.

## 12. LSA Type 8 — External Attribute LSA (사실상 미사용)

Type 8도 Type 6과 비슷한 처지입니다. "BGP의 세세한 속성(attribute)까지 OSPF 쪽지에 실어 나르면 어떨까"라는 아이디어로 만들어졌지만, **Cisco를 포함한 대부분의 벤더가 아예 구현하지 않았습니다.** 그런 정보가 필요하면 지금은 MP-BGP가 대신 처리합니다. Type 6·Type 8 둘 다 "번호는 있지만 실제로 눈으로 볼 일은 없다"는 타입입니다.

## 13. LSA Type 9 — Opaque LSA (Link-local)

지금까지 나온 쪽지들은 전부 OSPF가 내용을 직접 읽고 이해하는 것들이었습니다. Type 9~11 **Opaque LSA**는 다릅니다. "Opaque(불투명)"라는 이름 그대로, OSPF는 안에 뭐가 적혀 있는지 **읽지도 않고** 그냥 옆으로 전달만 해주는 **소포 배달** 역할만 합니다. 내용물은 다른 기능(확장 프로그램)이 알아서 꺼내 씁니다. 이 셋을 구분하는 기준은 오직 하나, **얼마나 멀리까지 배달해주냐(플러딩 범위)** 입니다.

Type 9는 그중에서도 **바로 옆 이웃까지만** 배달합니다. 예를 들어 R1이 OSPF 프로세스를 재시작하기 직전, 바로 옆 네이버인 R2·R3에게 **Grace LSA**라는 Type 9 소포를 보내 "나 잠깐 재시작하니까 토폴로지에서 지우지 말아줘"라고 부탁합니다. 옆 라우터만 알면 되는 얘기라서 더 멀리 퍼뜨릴 필요가 없는 것입니다.

## 14. LSA Type 10 — Opaque LSA (Area-local)

Type 10은 Type 9보다 한 단계 넓게, **영역 전체까지** 배달됩니다. 예를 들어 R1-R2 구간에 **MPLS Traffic Engineering**을 켠다면, 일반 LSA가 담지 못하는 "이 링크에 우선순위별로 대역폭이 얼마나 남았는지" 같은 세세한 정보를 Type 10 소포에 실어 Area 0 전체에 뿌립니다. OSPF는 이 내용을 안 읽고, 각 라우터의 TE 프로세스가 따로 열어서 자기만의 **TED(Traffic Engineering Database)**를 만드는 데 씁니다.

**Segment Routing**을 켰을 때 각 프리픽스의 SID(Segment ID) 정보가 오가는 것도 같은 Type 10입니다. MPLS TE나 Segment Routing을 안 쓰는 일반적인 OSPF 환경에서는 이 항목이 보통 비어 있습니다.

## 15. LSA Type 11 — Opaque LSA (AS-wide)

Type 11은 배달 범위가 **OSPF 도메인 전체**로, Type 5 External LSA와 비슷하게 모든 영역에 걸쳐 퍼집니다(Stub·NSSA 영역은 역시 제외). "전체 라우터가 다 알아야 하는 불투명 정보"를 위해 만들어졌지만, 실제로 그렇게까지 넓은 범위가 필요한 기능이 거의 없어서 **실무에서는 보기 드뭅니다.** MPLS TE·Segment Routing처럼 Opaque LSA를 쓰는 기능 대부분은 영역 하나로 충분해서 Type 10을 씁니다.

## 16. 라우팅 테이블 표시와 LSA 타입 정리

이 시리즈의 [OSPF 기본 설정](/posts/04-ospf-basic-config/), [OSPF Multi-Area Configuration](/posts/05-ospf-multi-area/)에서 이미 다룬 라우팅 테이블 표시들을 LSA 타입과 연결해서 정리하면 다음과 같습니다.

| 라우팅 테이블 표시 | 의미 | 어떤 LSA에서 나오는가 |
| --- | --- | --- |
| **O** | Intra-area(영역 내부) | Type 1 Router LSA |
| **O IA** | Inter-area(영역 간) | Type 3 Summary LSA (ABR이 생성) |
| **O E1 / O E2** | External(외부, 일반 영역) | Type 5 External LSA (ASBR이 생성) |
| **N1 / N2** | External(외부, NSSA 영역) | Type 7 NSSA External LSA → ABR이 Type 5로 번역 |

우리 토폴로지로 정리하면: R1이 R3의 루프백을 **O**(Cost 1)로, R2가 그걸 R1에게서 받아 **O IA**(Cost 2 + 1 = 3)로, R4가 R2에게서 받아 **O IA**(Cost 4)로 보는 흐름 전체가, 결국 "이 경로 정보가 어떤 LSA 타입을 거쳐서 왔는가"를 그대로 드러내는 것입니다.

## 17. 결론

OSPF의 11가지 LSA 타입을 하나의 토폴로지(R1·R2 = ABR, R3 = Area 1 + ASBR, R4 = Area 2)로 처음부터 끝까지 추적했습니다.

- Type 1(Router)·Type 2(Network)는 영역 내부에만 머무는 기본 LSA — R1-R2 구간에서 point-to-point/transit/stub 세 가지 Link Type과 DR의 Network LSA를 모두 확인했습니다.
- Type 3(Summary)·Type 4(Summary ASBR)는 ABR(R1, R2)이 영역 간 연결성을 위해 재생성하며, R3의 루프백 Cost가 1 → 2 → 3 → 4로 누적되는 과정을 추적했습니다.
- Type 5(External)·Type 7(NSSA External)은 ASBR이 된 R3의 재분배 정보를 전달합니다(Type 7은 NSSA 전용, ABR이 Type 5로 번역).
- Type 6·Type 8은 사실상 미사용 타입입니다.
- Type 9/10/11은 모두 Opaque LSA로, 플러딩 범위(link-local/area-local/AS-wide)만 다릅니다.
- 라우팅 테이블의 O / O IA / O E1·E2 / N1·N2 표시는 각각 Type 1 / Type 3 / Type 5 / Type 7 LSA를 반영합니다.

> 이 문서의 `show ip ospf database ...` 예시들은 실제 장비 캡처가 아니라, 위 토폴로지·코스트 값에 맞춰 형식과 계산을 정확히 재현한 **예시 출력**입니다. LS age·Seq Number·Checksum 같은 세부 값은 참고용이며 실제 장비 출력과는 다를 수 있습니다.
