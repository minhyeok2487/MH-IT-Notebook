## LSA란 무엇인가

LSA(Link-State Advertisement)는 프로토콜도 알고리즘도 아니고, **라우터가 뿌리는 자기소개 쪽지 한 장**입니다. "나는 R1이고, 내 인터페이스는 이렇게 생겼고, 이웃은 이렇다" — 딱 이 정보만 담은 작은 데이터 조각입니다.

- 라우터가 자기 링크 정보를 LSA라는 쪽지에 적어서 → 이웃에게 뿌리고(플러딩) → 이웃도 그대로 복사해서 또 뿌립니다.
- 영역 안 모든 라우터가 이 쪽지들을 다 모아 보관하는 서랍이 **LSDB**입니다.
- LSDB에 쌓인 쪽지를 전부 조합하면 네트워크 전체 지도가 완성되고, 그 지도로 SPF를 계산해 최단 경로를 뽑습니다.

타입이 11개나 되는 이유는 쪽지 양식이 상황마다 다르기 때문입니다 — 내용물은 다 "여기 뭐가 있다"는 사실 보고서이고, **누가 쓰는지 · 어디까지 퍼지는지**만 다릅니다.

## 이 글에서 쓰는 토폴로지

- **R1**과 **R2**는 ABR입니다. 둘은 이더넷으로 직접 연결되어 Area 0을 이룹니다.
- **R3**는 Area 1 안에만 있고 루프백 `3.3.3.3/32`를 가지며, 나중에 RIP도 재분배하며 ASBR이 됩니다.
- **R4**는 Area 2 안에만 있고 루프백 `4.4.4.4/32`를 가집니다.

이 네 대만으로 Type 1(Router LSA)의 point-to-point·transit·stub 링크 타입부터, Type 2(Network LSA), Type 3(Summary), Type 4(Summary ASBR), Type 5(External), Type 7(NSSA External)까지 전부 추적합니다.
